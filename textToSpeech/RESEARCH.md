# Research Notes for Text-to-Speech (TTS) Feature

## Overview
This document contains research and insights related to the Text-to-Speech (TTS) feature integrated into the AI Interview Platform.

## TTS in This Project
- The project uses the `gTTS` (Google Text-to-Speech) Python library for generating speech audio from text.
- TTS is used to vocalize interview questions generated by Google Gemini AI, helping replicate a realistic interview environment.

## How It Works
- The backend endpoint `/api/interview/{session_id}/question/{question_index}/audio` handles TTS generation.
- Given a session ID and question index, it fetches the question text and language.
- Uses `gTTS` to convert the question text to speech audio in the specified language.
- The audio is sent as an MP3 stream to the frontend.

## Why `gTTS`?
- Provides easy integration with Google Translate's TTS service.
- Supports multiple languages, aligning with the project's multilingual capabilities.
- Simple API for synchronous TTS generation.

## Potential Limitations
- Relies on Google Translate service, which may have rate limits or availability concerns.
- Audio generation is synchronous and uses temporary files, which might not be optimal for high concurrency.

## Alternative Options
- **Google Cloud Text-to-Speech API**: More robust, higher quality, supports customization (voice, pitch, speed), but requires separate billing.
- **Amazon Polly**: Similar to Google Cloud TTS, offers neural voices and customization.
- **Azure Cognitive Services TTS**: Another enterprise-level option with rich features.
- **Open Source Solutions**: e.g., `pyttsx3` for offline TTS but with limited voice quality.

## Future Considerations
- Move to asynchronous TTS generation to handle concurrent requests efficiently.
- Implement caching for audio files to avoid regenerating audio for repeated questions.
- Add support for voice selection and customization.
- Explore more natural sounding voices for better user experience.
